# Fix Admin Portfolio “Simulate” Preview Isolation

## Overview — what we're changing and why
The admin portfolio simulator currently renders theme previews directly inside the admin page DOM, which causes layout/style interference (sidebar/admin shell behavior bleeding into preview). We will isolate preview rendering so it behaves like a real standalone portfolio, while keeping the current admin controls (theme/device/mode/accent). This will make preview quality consistent, clean, and production-like for all portfolio templates.

## Affected files
- `client/src/pages/admin/PortfolioManagement.jsx` — replace direct in-modal renderer with isolated preview embedding and preserve existing simulator controls.
- `client/src/App.jsx` — add a dedicated route for isolated portfolio preview rendering (no admin shell/sidebar).

## Risks & edge cases
- **Provider dependencies:** If themes rely on app-level providers/context, the isolated route must include the minimal required wrappers.
- **Asset/font parity:** Standalone preview route must load same fonts/assets so preview looks identical to production portfolios.
- **Viewport-dependent themes:** Themes using `vh`/layout assumptions may need `html, body, #root` height handling in isolated route context.
- **Large payload transport:** If passing full demo payload via URL, encoding size can be an issue; prefer route state/postMessage if needed.
- **Dark/light mismatch:** Ensure preview mode toggle maps exactly to `customThemeMode` behavior used by `PortfolioThemeRenderer`.
