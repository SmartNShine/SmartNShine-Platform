# Resume QR Code Feature Implementation Plan

## Overview — what we're changing and why
We are adding a Resume QR Code feature in the resume editor so users can paste a portfolio/GitHub/LinkedIn URL and instantly get a scannable QR preview. Users can download the QR as PNG and optionally insert it into the resume header. This is a client-side enhancement that fits the existing editor UI patterns and requires no backend API changes.

## Affected files — bullet list of `path` — one-line role
- `client/src/components/editor/sections/PersonalInfoSection.jsx` — add URL input, live QR preview, download action, and “insert in header” toggle in the contact section UI.
- `client/src/components/editor/constants/demoResumeData.js` — extend resume data defaults with `qrCode` object for safe initialization.
- `client/src/components/editor/hooks/useResumeDataOperations.js` — ensure QR fields are persisted/updated alongside other resume fields.
- `client/src/components/editor/preview/ResumePreview.jsx` — pass QR data through preview rendering so enabled QR appears in header output.
- `client/src/components/templates/ClassicTemplate.jsx` — render optional QR image in resume header when enabled and valid.
- `client/package.json` — add QR generation dependency (`qrcode`) for client-side PNG data URL generation.

## Steps — numbered, concrete, in execution order; each step names the file(s) and the specific change
1. **Add QR dependency**
   - **File:** `client/package.json`
   - Add `qrcode` dependency to support generating QR PNG data URLs in browser.
   - Run install to update lockfile accordingly.

2. **Extend resume default data shape**
   - **File:** `client/src/components/editor/constants/demoResumeData.js`
   - Add a new top-level object:
     - `qrCode.url: ""`
     - `qrCode.enabled: false`
     - `qrCode.imageDataUrl: ""`
   - Ensure defaults are present in demo/seed resume data so old/new sessions don’t break.

3. **Wire QR data handling in resume operations**
   - **File:** `client/src/components/editor/hooks/useResumeDataOperations.js`
   - Ensure update helpers can set nested QR fields (`qrCode.url`, `qrCode.enabled`, `qrCode.imageDataUrl`) without mutating state.
   - Add safe fallback initialization (`qrCode` object) when loading resumes that predate this feature.

4. **Build QR UI in personal/contact section**
   - **File:** `client/src/components/editor/sections/PersonalInfoSection.jsx`
   - Add a “Resume QR Code” block styled like existing editor cards.
   - Add URL input field with placeholder for portfolio/GitHub/LinkedIn.
   - Validate URL as `http/https`; show inline invalid state for malformed values.
   - On valid URL change, generate QR PNG data URL using `qrcode` and store in `qrCode.imageDataUrl`; keep it live-updating.
   - Render a preview image from `qrCode.imageDataUrl`.
   - Add “Download PNG” button:
     - disabled unless `imageDataUrl` exists.
     - uses temporary anchor download flow with filename `resume-qr.png`.
   - Add “Insert into resume header” checkbox/toggle bound to `qrCode.enabled`.

5. **Inject QR into editor preview pipeline**
   - **File:** `client/src/components/editor/preview/ResumePreview.jsx`
   - Ensure the template render path receives `resumeData.qrCode`.
   - Guard against missing `qrCode` on older data with fallback object.
   - Keep preview stable when URL is invalid or QR generation not yet complete.

6. **Render optional QR in resume header template**
   - **File:** `client/src/components/templates/ClassicTemplate.jsx`
   - In header layout, conditionally render QR image only when:
     - `resumeData.qrCode.enabled === true`
     - `resumeData.qrCode.imageDataUrl` is non-empty
   - Place QR on right side of header with compact fixed size suitable for print/PDF (scannable but unobtrusive).
   - Add alt text (`"Resume QR code"`) and maintain existing spacing/typography.
   - Ensure header does not overflow or break on smaller page widths.

7. **Regression verification**
   - **Files touched above**
   - Verify flow end-to-end:
     - paste valid URL → live QR preview appears
     - Download PNG works
     - toggle insert → QR appears/disappears in preview header
     - invalid URL blocks generation and shows error
     - old resumes without `qrCode` still render and edit correctly
   - Verify light/dark theme visual consistency in editor UI block.

## Risks & edge cases — what to watch for
- **Backward compatibility:** Existing resumes may not have `qrCode`; always apply fallback object before reading nested fields.
- **Template layout breakage:** Header QR placement can collide with long names/contact lines; keep fixed dimensions and robust flex wrapping.
- **Scannability in exported PDF:** Use sufficient QR resolution and avoid overly small rendered size.
- **Invalid URLs and noisy input:** Debounce/regenerate carefully and avoid persisting stale/invalid `imageDataUrl`.
- **Client performance:** Re-generating on each keystroke can be heavy; prefer generation after short debounce or on valid input transitions.
