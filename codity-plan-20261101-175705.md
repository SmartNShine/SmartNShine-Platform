# Admin Portfolio Preview Parity & Layout Stabilization

## Overview — what we're changing and why
The admin Portfolio section currently renders a generic simulator using static sample data, which causes mismatch with actual user portfolios and poor template fidelity. We will make each admin preview render the selected portfolio’s real saved content, with polished fallback fillers only for missing fields. We will also stabilize the preview container so admin layout/sidebar styles do not collapse or distort the simulation viewport. This ensures the admin sees a clean, accurate representation of each portfolio template.

## Affected files
- `client/src/pages/admin/PortfolioManagement.jsx` — replace static simulator flow with real-portfolio preview pipeline, smart fallback mapper, and stable preview viewport behavior.
- `client/src/App.jsx` (reference only, no functional change expected) — confirm theme parity against public template routes at `162-165`.

## Steps
1. **Locate and replace static simulator source in `client/src/pages/admin/PortfolioManagement.jsx`**
   - Remove reliance on `SAMPLE_PORTFOLIO_RESUME` as the primary render object (defined at `78-153`).
   - Keep sample fragments only as fallback values for missing sections, not as full replacement data.

2. **Add a preview data normalizer in `client/src/pages/admin/PortfolioManagement.jsx`**
   - Create a helper (e.g., `buildPreviewData(portfolio)`) near existing simulator state logic (starts around `155+`).
   - Input: selected admin portfolio row object.
   - Output: exact data shape expected by `PortfolioThemeRenderer` (imported at `47`).
   - Rules:
     - Use real saved values first (`name`, `title`, `summary`, `projects`, experience, links, etc.).
     - Inject polished defaults only for empty/missing fields (hero summary, skills groups, 1–2 projects, timeline snippets).
     - Preserve portfolio-specific theme and metadata.

3. **Wire preview-open action to selected portfolio payload in `client/src/pages/admin/PortfolioManagement.jsx`**
   - In the existing “simulate/preview” button handler for each portfolio row/card, store the selected portfolio object and pass it through `buildPreviewData(...)`.
   - Ensure each preview reflects the clicked portfolio, not last/global/mock data.
   - Keep `PreviewErrorBoundary` (`50-76`) wrapping renderer output.

4. **Stabilize preview viewport and stop admin layout bleed in `client/src/pages/admin/PortfolioManagement.jsx`**
   - In the simulator modal/body, wrap `PortfolioThemeRenderer` in a bounded preview canvas:
     - fixed-height container with `overflow-auto`
     - explicit width presets for desktop/tablet/mobile toggles (icons imported at `20-22`)
     - avoid flex shrink/collapse by using stable width classes and `min-w-0`/`flex-none` where needed.
   - Prevent sidebar/layout CSS from distorting preview by isolating rendering surface styles in the modal content container.

5. **Enforce theme parity in `client/src/pages/admin/PortfolioManagement.jsx`**
   - Resolve selected theme via existing `portfolioThemes` registry import (`46`) and pass that to `PortfolioThemeRenderer`.
   - If theme key is missing/unknown, fallback to a clean default theme and show a small warning indicator in preview controls.
   - Confirm behavior aligns with public routes in `client/src/App.jsx:162-165`:
     - `/tech-portfolio`
     - `/smartnshine-portfolio`
     - `/magazine-portfolio`

6. **Improve boundary diagnostics in `client/src/pages/admin/PortfolioManagement.jsx`**
   - Keep `PreviewErrorBoundary` and expand displayed context to include portfolio id/theme (safe, non-sensitive) when render fails.
   - This speeds debugging of malformed portfolio payloads.

7. **Validation pass (manual)**
   - Open `/admin/portfolios`, preview multiple different portfolios, confirm each shows its own data.
   - Verify sparse/incomplete portfolios still look polished via partial fallback fills.
   - Verify desktop/tablet/mobile toggles render proportionally and without collapse.
   - Confirm admin sidebar/layout no longer visually interferes with preview canvas.

## Risks & edge cases — what to watch for
- **Schema mismatch** between stored portfolio objects and `PortfolioThemeRenderer` expected structure can still break sections if not normalized defensively.
- **Over-fallback risk**: avoid replacing valid but minimal user data with dummy content; only fill truly missing values.
- **Unknown theme ids** in legacy data may produce blank previews unless explicit fallback mapping is applied.
- **CSS inheritance bleed** from admin layout/theme classes can reappear if preview container constraints are incomplete.
- **Large project arrays/media** may impact modal performance; keep preview scrollable and avoid unbounded rendering dimensions.
